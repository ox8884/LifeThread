# LifeThread English/Korean Architecture

Status: core MVP architecture, not a post-MVP translation pass

## 10. Bilingual and internationalization architecture

One LifeThread record serves both English and Korean. Locale changes presentation only; it never duplicates the thread or writes a canonical revision.

### Three content classes

1. **Canonical structured data:** language-neutral IDs, statuses, types, dates, confidence, provenance, relationships, and revisions.
2. **Original content:** user goals, notes, filenames, files, quoted evidence, identifiers, and corrections preserved verbatim with source-language metadata.
3. **Localized derived content:** UI labels and AI-generated summaries/explanations/drafts stored or generated separately for a display locale.

Translations and localized summaries are never evidence and never become canonical truth.

## UI localization

- Locale dictionaries live in `messages/en.json` and `messages/ko.json`.
- Components use translation keys; no user-facing literal is embedded in TSX except language-neutral user content.
- Dictionaries cover navigation, buttons, forms, placeholders, empty/loading/error states, canonical status/type labels, confirmations, task controls, timeline/evidence labels, AI notices, demo/limitations labels, validation text, and accessibility names/descriptions.
- CI compares key sets and fails on missing/orphaned keys.
- A visible switcher supports `en` and `ko`; session/cookie preference remembers the selection.
- Dates, times, numbers, pluralization, and relative times use locale-aware formatters.
- Layout tests cover Korean/English length expansion, wrapping, focus, and keyboard navigation.

Canonical examples:

| Internal value | English | Korean |
| --- | --- | --- |
| `waiting` | Waiting | 대기 중 |
| `completed` | Completed | 완료됨 |
| `blocked` | Blocked | 진행 불가 |
| `uncertain` | Uncertain | 불확실 |
| `overdue` | Overdue | 기한 지남 |

## Original and localized content

`LocalizedContent` is keyed by entity ID, field, revision ID, locale, and generator version. It includes source locale and translation status. It cannot overwrite the entity’s original field.

Fallback order:

1. Matching localized content for the current revision.
2. Verbatim original content with a visible “original language” indicator.
3. A localized unavailable message; never fabricated text.

Names, organization/product names, filenames, technical identifiers, error codes, and tracking numbers remain unchanged unless the user explicitly edits them.

## Bilingual input and AI output

Goals, tasks, corrections, and evidence may be Korean, English, or mixed. Language detection is metadata, not routing. All inputs use the same strict CandidateDelta schema and reconciliation service.

AI user-facing prose follows selected display locale:

- goal interpretation;
- milestones/tasks and explanations;
- fact/timeline/current-state prose;
- open loops, risks, deadlines, waiting states;
- next action and alternatives;
- change explanations and communication drafts.

Meaning and evidence links are preserved; the pipeline does not perform blind word-for-word translation.

## Locale invariants

- EN -> KO -> EN switching leaves thread ID, version, canonical JSON hash, evidence IDs, source references, task origins, and confirmation state unchanged.
- Korean evidence summarized in English still cites the Korean original.
- English evidence summarized in Korean still cites the English original.
- Mixed-language strings preserve embedded names, codes, and identifiers.
- Missing localization is visible and does not block access to the original.
- Generated bilingual drafts are separate derived artifacts, never external actions.

## Acceptance fixtures

1. Korean free-form goal -> usable English tentative plan.
2. English free-form goal -> usable Korean tentative plan.
3. Mixed Korean/English evidence -> schema-valid facts and citations.
4. Korean evidence -> English current-state summary with unchanged original.
5. English evidence -> Korean summary with unchanged original.
6. Locale round trip -> zero canonical writes and stable canonical hash.
7. Missing generated translation -> visible original fallback.
8. Dictionary key parity and no hard-coded user-facing TSX strings.

Natural-language fixtures receive review for Korean fluency and English judge clarity, while machine assertions cover schema, IDs, citations, locale keys, and zero-mutation behavior.
